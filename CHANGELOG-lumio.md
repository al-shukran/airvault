# Lumio Changelog

All notable changes to Lumio. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). See [CONTRIBUTING.md](CONTRIBUTING.md) for how to add an entry, and for the choices we made where that specification is silent.

## [Unreleased]

## [1.1.0] - 2026-11-28

**Upgrading:** Set Lumio up again and pair it with Lensly again. Lumio's database is recreated on the first start after updating, so nothing stored in the older version is carried over.

### Fixed

- A Bitcoin account whose scan has grown too large for the cache now shows no balance after a restart until it is scanned again, instead of its last smaller balance. [Issue #1388](https://github.com/al-shukran/airvault/issues/1388)
- A Bitcoin send now asks the server for its change address when you build it, and a send that was just broadcast keeps its change address, so two sends in a row no longer pay change to the same address. [Issue #1085](https://github.com/al-shukran/airvault/issues/1085)
- A Bitcoin transaction no longer shows as pending, or a block short, when the server that gave the chain tip is behind the one that listed the transaction. [Issue #1137](https://github.com/al-shukran/airvault/issues/1137)
- A Bitcoin, Algorand or Solana transaction that the network already holds no longer reads as failed: sending it again after a timeout, or after another device sent it, now ends on the sent page. [Issue #1334](https://github.com/al-shukran/airvault/issues/1334)
- A Duress Password session no longer walks every row of the real vault's cache when it trims its own, so a full real cache cannot slow it down or make it fail. [Issue #1305](https://github.com/al-shukran/airvault/issues/1305)
- A Duress Password setup that hits any unexpected error while it builds the decoy now undoes it, or erases the vault when it cannot, instead of leaving a half-built decoy behind. [Issue #1617](https://github.com/al-shukran/airvault/issues/1617)
- A Solana send with the Priority Fee switch on now shows and reserves the same fee that Lensly shows for it, counting the price instruction itself. [Issue #1484](https://github.com/al-shukran/airvault/issues/1484)
- A coin logo is now decoded within a size limit, and a logo that is no image or declares too many pixels is neither kept nor shown. A failed write to the cache no longer crashes Lumio while a logo loads. [Issue #1376](https://github.com/al-shukran/airvault/issues/1376) [Issue #1380](https://github.com/al-shukran/airvault/issues/1380)
- A coin logo that cannot be decoded is no longer kept: a damaged one is dropped and downloaded again instead of leaving the letter icon in place until the cache is cleared. [Issue #1395](https://github.com/al-shukran/airvault/issues/1395)
